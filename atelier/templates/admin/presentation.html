INTEGRITY IN ACTION

The rules behind the room.

Constraints protect the stored data. Transactions keep each multi-record operation together. These definitions come from the running database and application.

Keys & relationships

Non-null foreign keys require existing parents. Composite keys stop duplicate exhibition memberships. A unique index allows only one open lot per artwork.

Valid bids & sales

Triggers reject low bids and preserve accepted history. A sale must use the highest qualifying bid, the correct collector, and that bid’s exact price.

All or nothing

BEGIN IMMEDIATE serializes writers. A failed close rolls back the collector, sale, and status changes together. Closing twice does not create another sale.

BROWSER → APPLICATION → DATABASE → RESULT

Follow the request.

The artwork is the front of the experience. This is what happens behind it.

  1. 01

    A visitor takes an action

    A form submits a bid amount, lot ID, and CSRF token. The server reads the bidder identity from the authenticated session.

  2. 02

    Flask checks access & input

    The route checks the user’s role and converts rupees to integer paise. Staff-only operations use separate protected routes.

  3. 03

    The service opens a transaction

    Parameterized SQL checks the latest state. SQLite constraints and triggers enforce relationships, amounts, and immutable history.

  4. 04

    Commit, then render the result

    On success, SQLite commits. On failure, it rolls back. The browser is redirected to a freshly queried page with a clear result message.
